(`~/.lunarclient/profiles/surv`), Solas 3.8 with the user's settings, on the server misc1.glaaaspenis.de.

## 2. ~10 fps after about a minute

`logs/latest.log` grew to ~39 MB in 6 minutes. ~10,000 times:

```
[Render thread/ERROR]: [LC Error] Invalid Offscreen Submit Call
...: RenderManager received a submit after COLLECTING stage! Stage: RENDERING_OFFSCREEN
	at net.minecraft.client.renderer.entity.layers.CapeLayer...lunar$redirectRenderCloak...
	at net.minecraft.client.renderer.entity.LivingEntityRenderer.submit
	...
	at net.minecraft.client.renderer.LevelRenderer.handler$...$iris$renderTerrainShadows
```

Lunar's cosmetic capes refuse submits made while Iris' shadow pass renders player entities (stage
RENDERING_OFFSCREEN). It starts after joining the server (other players with capes), once per player per
frame, each with a full stack trace: that alone can drag the frame rate down. The shadow pass only runs on
Vulkan since M3, so this is new with the M3 build.

Ideas: skip `CapeLayer` (or all Lunar cosmetic layers) while `ShadowRenderingState.areShadowsCurrentlyBeingRendered()`,
or catch/suppress Lunar's exception for shadow-pass submits; check how GL Iris in Lunar avoids it (if it does).
Check fps again afterwards; if still low, profile (JFR, `-PjfrProfile`).

Also in the log: stretches of exactly 1 fps ("pacing 1003 ms") alternating with 110-170 fps. That looks like
dynamic-fps throttling the unfocused window (Lunar profile has dynamic-fps), not a render problem; confirm.

Other log notes: Frame Generation x2 is active at times (shown 160 fps from ~80 rendered); "Resizing Dynamic
Transforms UBO" up to 128 on the server (many entities), harmless.
